# Can EHR timestamps measure ophthalmic technician workload?

Compare EHR timestamps with observed technician work before using them to forecast staffing in an ophthalmology clinic.

By Thomas Wagenberg · November 17, 2026 · 3 min read

The practical takeaway

EHR timestamps can measure how long a patient spent between recorded events. Before using that interval as technician workload, check which events create the timestamps and compare them with observed work. Keep waiting, active work and work done by multiple technicians separate.

## What does the clock actually measure?

I'd ask the team to walk through one visit and show me what creates each event. A workup might start when someone changes the patient status. The next event might come when someone opens a chart or marks a room ready. Ask who creates each mark and whether they usually make it as the work happens or later.

Give the interval a name that matches those events. If it covers the time from workup start to ready for the provider, call it elapsed workup-to-ready time. That can help explain flow even when it includes waiting, dilation or a technician stepping away to help another room.

Hribar and colleagues observed workflows in four outpatient ophthalmology clinics and compared observation-based times with times computed from EHR logs. I'd take their method of comparing the two clocks and test it on our own workflow before using any interval for staffing.

## Compare the EHR interval with active minutes

1. **Define the work.** Agree on which tasks count as technician work. Decide how you'll handle preparation, documentation, interruptions and work shared by two people.
2. **Observe a small spread of visits.** Include a routine visit and an imaging-heavy visit, and look at more than one session. Have the team use a short log of task start, stop and role. Use approved internal tools and keep identifiers out of any planning summary.
3. **Reconcile each mismatch.** Compare the same visit and segment in both clocks. Note delayed status changes, missing starts, wait time and work between events. If two technicians handle a task together for five minutes, count ten technician minutes for capacity planning.
4. **Choose what the interval is fit for.** Set a local error tolerance based on the staffing decision. If an interval routinely includes unattended time or misses tasks, keep it as a flow measure. If the match holds across the work you need to plan, use it as a local proxy and recheck it when the workflow changes.

## A fictional 24-minute interval

The chart shows 24 minutes between workup start and ready. In this synthetic example, a technician spends eight minutes doing the workup. The patient waits 12 minutes. The same technician returns for four minutes of testing. That's 12 minutes of active technician work and 24 minutes of elapsed time. A team planning the session needs those two labels.

If another technician joins for two minutes of the test, the elapsed time stays 24 minutes, but the staffing total rises to 14 technician minutes. I'd keep a note about where those minutes landed, because two tasks at the same time can still compete for coverage.

## What should go into the staffing forecast?

Bring the event definitions, the comparison notes and the visits you couldn't match. Keep active work separate from waiting and flag any proxy that hasn't been checked. If you have a mixed set of timestamps, I'd start by using them to find the sessions that need a closer look. Build the staffing estimate from the work you can account for.
